# Contributing

Code contributions are welcome. Content contributions are not, and the
distinction matters.

## Content is not contributed

Cards are generated by Claude on a schedule and reviewed by hand before
publication. `data/feed.json` is written by that pipeline, not by people.

**Pull requests that modify `data/`, `generator/` or `.github/workflows/` will
not be merged.** A card that confidently teaches the wrong thing is worse than
no card, so everything published passes through one reviewer. This is enforced
by [CODEOWNERS](.github/CODEOWNERS).

If you have a card worth adding, open an issue with the substance in it.

## Running your own feed

The pipeline is designed to be forked. Point it at your own repo and your
extension will read your feed rather than this one:

```bash
npm run set-feed-url    # derives the Pages URL from your git remote
```

Nothing is shared between forks — separate generation, separate review,
separate published URL.

## Code changes

```bash
npm install
npm run typecheck   # all four TypeScript projects
npm run build
```

Design work is much faster through `dev/preview.html`, which runs the real
webview bundle in a browser against the seed feed, than through an F5 cycle.

Two things the tooling will not catch for you:

- `npm run build` does **not** typecheck the webview — Vite strips types with
  esbuild. Run `npm run typecheck` before considering a UI change done.
- Renaming a settings key silently breaks it for anyone who has set it.
  `FeedSession.sanitise` drops values retired from an enum, so add there when
  you retire one.
